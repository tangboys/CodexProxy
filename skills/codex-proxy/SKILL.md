# Codex 专用代理

## 桌面版可视化入口

用户要求“打开代理管理”“打开代理设置”或使用桌面版时，运行本技能的 `codex-proxy.ps1 desktop`，打开 C# WPF 原生 EXE。不要尝试把自定义设置注入 Codex 原生设置页。

面板提供节点名称、名称推断的国旗、协议、延迟、可用状态和当前选择；当前连接也显示国旗及普通测速延迟。支持点击切换、自动选择、检测和刷新。“订阅设置”可保存多个具名订阅，选择一个“保存并启用”；普通“保存”只添加或修改备用订阅，保存正在使用的订阅则验证并更新配置。启用失败保留当前订阅和节点，节点不合并；旧单订阅自动迁移。左下显示专用内核上下行速率与累计流量；套餐区单独显示订阅服务报告的已用、总量、剩余及到期，服务未提供时显示未知。“刷新用量”只更新套餐信息，“刷新节点”更新节点并在后台刷新套餐。“流量日志”每秒采样连接目标和节点链路，保留本次运行最近 300 条，可能略过短连接。节点和凭据留在本机；关闭窗口收起到托盘，“退出程序”清理本工具拥有的内核。

0.11 每次新开管理器默认停止，停止时仍可查看持久节点快照、上次延迟和检测时间，预选手动节点或自动模式，再点击“启动代理”与“启动 Codex”。停止时“检测节点”和“刷新节点”短时使用不同端口的隔离内核，完成后清理，正式代理保持停止；“检测 Codex”仍需代理已启动。套餐信息独立从订阅响应头读取，支持标准及兼容前缀，按订阅持久缓存，打开或切换订阅时后台刷新，失败显示上次读取并提示。“刷新用量”仅更新套餐，“刷新节点”更新节点并后台刷新套餐。内核就绪与 Codex 实际接入分别显示。“停止代理”仅关闭本工具拥有的正式内核，保留 Codex 和本地转发桥；同端口重开后请求可重试，已有流式请求可能失败。停止期间普通轮询、保存配置或预选不会开启正式代理。不要把缓存可用状态、核心就绪或网络检测通过说成真实模型请求成功。

面板分为“概览、节点、日志、设置”。概览显示连接/套餐和启动按钮，节点与日志独立成页。“设置 → 常规”切换简体中文/English、保存状态刷新间隔（5/10/30/60 秒）、检测或选择 Codex 程序路径，并打开订阅编辑器；“设置 → 内核”选择 Mihomo；“设置 → 更新”内嵌显示版本比较，查询失败时保留已知版本并标明缓存/备用来源，不把失败说成已是最新版。流量仍每秒采样。节点名和订阅名保留原文。0.5 起当前 Windows 用户会话只允许一个管理器，重复启动唤起已有窗口，包括托盘窗口。升级旧版时先由用户点击“退出程序”，再打开新版 EXE。

0.6 提供浅蓝界面和“内核设置”：EXE 内置 Mihomo，运行时提取到私有状态目录的 cores 缓存，首次配置优先内置。已保存的外部路径保留，用户可从检测列表选择内置、Clash Verge/v2rayN 的兼容 Mihomo 或手动选择。运行中应用时短暂重启专用代理，失败尝试恢复原内核；停止时只保存选择。只允许停止本工具拥有的进程。可手动检查 Mihomo 官方稳定版更新、打开官方发布页，不自动下载或替换。当前开发阶段直接使用 EXE，不提前生成安装包。

首次在面板保存订阅并启动代理后，用户需要保存工作并完全退出旧的 Codex 桌面实例，再点击“启动 Codex”。EXE 启动时自动查找官方 Windows Store 安装及常见目录；未检测到时使用“选择程序”手选桌面 EXE，路径保存后在启动前再次校验，拒绝误选 CLI。为新桌面进程传入代理环境，并为其 Chromium 界面传入专用代理参数。**不要终止正在承载当前会话的 Codex，也不要声称能接管已经运行的桌面进程。**

“检测 Codex”通过临时独立内核逐节点检查 ChatGPT 用量接口和 OpenAI API，不改变主代理选择、不读取账号凭据、不发模型请求。结果区分网络可达、访问受限、连接失败和部分可达；悬停查看两端 HTTP 状态及检测时间。401 表示未认证但网络可达，403/429 可能涉及访问策略或限流，不能据此保证登录、地区资格或模型调用成功。结果在本次运行保留，订阅刷新或更换后须重新检测。该检查不改变现有自动优选策略。

只对独立测试验证过的范围作承诺：本机桌面 Chromium 已使用隔离配置测试代理接入，Rust app-server 已通过本地测试服务完成模型会话。真实订阅、登录及账号模型请求仍需要用户从启动器打开桌面版后验证。界面“已观察到代理连接”不等同于模型请求已成功。

管理器与下方 CLI 共用本地订阅配置和独立内核。管理器的代理已启动时，`test`、`select`、`auto`、`refresh` 可用于响应自然语言管理请求并复用现有内核，不改系统代理；管理器停止时，CLI 命令仍会临时启动自己的内核并在结束后清理。检查更新手动查询项目的 GitHub Releases，不自动安装。EXE 安装和路径绑定见 [references/usage.md](references/usage.md)。

## CLI 工作流程

使用本技能目录下的 `codex-proxy.ps1` 或 `scripts/codex_proxy.py`。终端菜单支持输入订阅和选择节点，后台使用独立的 Mihomo 实例。Mihomo 原生解析 YAML、URI 列表和 Base64 订阅，不把订阅交给第三方转换服务。

## 工作流程

1. 先运行 `status` 查看是否配置。首次运行 `setup`，输入订阅链接；有多个内核时优先复用本机 Mihomo，不下载来历不明的程序。只有缺少内核时阅读 [references/usage.md](references/usage.md) 中的安装说明。
2. 运行 `test`，按节点名称报告连通状态和延迟。用户点名节点时执行 `select "节点完整名称"`；要求自动选择时执行 `auto`。不能把超时节点或全节点失败报告为可用。
3. 用户在普通终端执行 `run` 启动带代理的 Codex。CLI 参数放在 `run --` 后，例如 `run -- resume --last`。首次未配置时先提示输入订阅。无参数进入菜单。
4. 在专用启动器启动的 Codex 会话里，技能的 `select` / `auto` / `refresh` 会复用当前代理内核；新建连接会用新节点，已建立的流式连接可能需要重试。普通终端中这些命令临时启动内核并保存选择，退出时清理。

命令示例（把路径替换为本技能的实际绝对路径）：

```powershell
& '<skill-dir>\codex-proxy.ps1' setup
& '<skill-dir>\codex-proxy.ps1' test
& '<skill-dir>\codex-proxy.ps1' select '节点名称'
& '<skill-dir>\codex-proxy.ps1' auto
& '<skill-dir>\codex-proxy.ps1' run
```

PowerShell 启动器自动找 Python 3，包括本机 Codex 随附运行时；也可直接运行 `python <skill-dir>/scripts/codex_proxy.py <命令>`。完整参数、故障排查与验证范围见 [references/usage.md](references/usage.md)。

## 必须保留的边界

- **不能在当前会话内给已经启动的 Codex 主进程注入代理环境变量。** 首次配置后必须通过启动器启动新的 CLI。没有网络时也不可能先调用在线 Codex 再让技能解决首次联网，直接运行启动器即可。
- 代理作用于启动器启动的 Codex 和继承环境的子进程；它不是按进程防火墙。不要承诺任意子工具都会遵守代理变量。远端网页搜索/云端连接器不受此本地代理控制。
- 不修改 Windows 系统代理、WinHTTP、TUN、路由、用户/系统环境变量、PowerShell profile 或 Codex 的持久配置；也不停止 v2rayN/Clash 的现有进程。若用户当前开了系统代理/TUN，需要自行关闭后判断其他软件是否直连。
- 订阅链接、节点凭据、控制器密钥只保存在用户本地状态目录，不在回复或日志摘要中回显。交互输入用隐藏输入；Codex 已拿到链接时，将其写入本地临时文本文件，用 `setup --url-file <绝对路径>` 导入并只删除该临时文件，不把链接放进 shell 命令。不要上传状态目录、订阅缓存或原始内核日志。
- 自动模式每 300 秒检测并选择延迟较低的可达节点，手动模式固定节点。默认检测 HTTPS 204 地址只能证明该测试地址可达，**不能证明 OpenAI 地区支持、账号权限、登录成功或模型请求成功**。用户可用 `setup --test-url ... --expected-status ...` 指定其服务的检查地址；实际 Codex 请求必须另行验证。
- 所有节点检测失败时，拒绝启动 Codex；不会回退到直连。订阅刷新失败时保留旧缓存并明确报告失败。退出启动器时只清理自己启动的内核。
