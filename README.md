# Codex Proxy

[English](README.en.md) · [Releases](https://github.com/tangboys/CodexProxy/releases) · [构建](docs/BUILDING.md) · [验证记录](TEST-RESULTS.md)

给 Windows x64 上的 Codex 桌面版提供独立代理的 C# / WPF 工具。支持多订阅单选、节点预选与测速、套餐用量、实时流量和中英文界面。

这是社区工具，与 OpenAI、v2rayN、Mihomo 或 Clash Verge Rev 没有官方隶属关系。Codex 桌面版需自行从官方渠道安装，本项目不提供 Codex、账号或代理订阅。

## 获取

当前版本 **0.12.0 预览版**从 [Releases](https://github.com/tangboys/CodexProxy/releases) 获取。下载 `CodexProxy.exe` 即可运行，.NET 运行时和 Mihomo 已内置；许可证、第三方通知与对应源码在同一 Release 和仓库中提供。预览版尚未完成运行验证。

本版不提供产品 ZIP 或安装包。自行构建会生成 `dist/0.12.0/CodexProxy.exe`，见[构建说明](docs/BUILDING.md)。后续如提供便携包，推荐使用完整的 `CodexProxy-<version>-win-x64.zip`；再分发时请同时保留许可和对应源码材料。GitHub 源码下载不是可运行程序。

## 快速开始

1. 完全退出旧 Codex Proxy，再打开 `CodexProxy.exe`。默认正式代理停止，不自动启动 Codex；关闭窗口会收起到托盘，完全退出使用“退出程序”。
2. 在“设置 → 常规”打开“订阅设置”，新增名称和 HTTP(S) 链接。“保存”存为备用，“保存并启用”选为当前订阅；一次只启用一个，不合并节点。可直接编辑或隐藏已保存链接。
3. 在“节点”页查看缓存节点、最后状态/延迟和检测时间，预选节点或自动模式。预选允许未检测或上次不可用节点，不代表节点已经可用。
4. 使用“节点”页的“检测节点”或“刷新节点”后，在“概览”点击“启动代理”。停止时检测/导入使用短时隔离内核，结束后仍停止；正式代理启动后应用保存的选择。“检测 Codex”当前仍要求正式代理已启动。
5. **最后验证真实 Codex**：保存工作并完全退出已有 Codex 桌面实例，再点击“启动 Codex”，发送一条消息确认真实登录和模型请求。路径会自动检测，也可手选桌面 EXE；已有实例或节点检测失败会提示。

“停止代理”结束本工具拥有的正式内核，保留 Codex 和本地转发桥，便于按原端口重新启动；已开始的流式请求可能需要重试。“退出程序”会清理自有内核与桥接，仍保留 Codex。不会结束其他代理软件的进程。

## 页面入口

- **概览**：当前节点、延迟、代理地址/端口、Codex 界面转发地址、接入状态和订阅套餐，以及启动/停止代理和启动 Codex。未就绪时显示目标端口，停止时标明本工具未监听。
- **节点**：节点选择、自动模式、普通测速、Codex 检测和刷新节点。
- **日志**：连接目标与节点链路，独立查看和清空。
- **设置**：常规页保存中英文、状态刷新间隔、订阅下载方式、代理端口和 Codex 程序路径；内核页选择兼容 Mihomo；更新页内嵌显示本机版本、发布版本、发布时间和比较结果。内核是代理引擎，本工具不安装流量拦截驱动。

状态刷新可设为 5、10、30 或 60 秒，保存在本机；流量和日志仍每秒采样。Tab 导航保留，焦点使用浅蓝反馈，移除默认虚线框。

在“设置 → 常规 → 网络设置”填写 1–65535 的专用代理端口，留空或“恢复自动”重新分配。修改前需停止代理，保存前检查 TCP/UDP 占用及控制端口冲突，启动前再检查。检测不保留端口，其他程序之后仍可能抢占；此时会提示失败。修改保留控制端口和认证信息，旧界面转发桥释放但不关闭 Codex；保存工作并完全退出旧 Codex，再从启动器打开以使用新端口。地址仅显示 `127.0.0.1`，HTTP/SOCKS5 认证仍由启动器处理。

订阅下载方式可手动选择，节点和套餐均按所选路径获取，不自动回退：

| 方式 | 使用条件 |
| --- | --- |
| 直连（默认） | 不使用普通 HTTP 系统/环境代理；其他软件的 TUN/透明转发仍可能影响连接。 |
| 系统代理 | 使用 Windows/当前进程默认代理，可能优先采用 `HTTP_PROXY` 等环境变量；首次导入可用。 |
| 当前专用代理 | 先通过已有节点启动本工具的代理，再更新订阅。无缓存时先改用直连或系统代理导入。 |

下载方式在下一次节点刷新、启用或重新启动内核时载入；已运行内核的 24 小时自动更新继续使用之前载入的方式。更改系统代理后请手动刷新节点。系统模式把订阅地址当前有效的 HTTP/HTTPS/SOCKS5 代理转成下载上游，不完整复现动态 PAC 或跨域重定向代理策略；不支持的协议或认证明确报错。节点订阅仍由 Mihomo 解析，保留 24 小时订阅更新和 5 分钟自动节点检测。

## 节点、套餐和本地流量

- 节点快照按订阅 URL 隔离持久保存。停止时可浏览和预选，普通测速会更新延迟与检测时间；国旗由节点名称推断，不保证真实地理位置。
- 取消自动选择会固定内核当前节点，不重新测速；停止时没有当前节点则使用列表选中节点或首个节点，保存为手动预选。普通切换和启动时的节点检查保持原样。
- 当前订阅也可删除：停止本工具拥有的代理并清空当前配置，其他订阅保留但不自动启用。之后需重新启用订阅、启动代理，并保存工作后完全退出旧 Codex 再启动，以应用新的代理端口和凭据。
- 多内核设置支持内置 **Mihomo v1.19.31** 或已安装的兼容 Mihomo。应用内核时停止状态保持停止；运行时切换可能短暂断连。Clash GUI、Xray 和 sing-box 不是可直接替换的 Mihomo。
- 套餐来自订阅服务商响应头。停止时可查看缓存，直连/系统模式可刷新，专用代理模式需先启动；显示已用/总量、剩余、到期和进度。请求失败保留同 URL 上次缓存并提示，成功但未提供有效字段显示未知。未知或 0 总量不表示无限。
- “刷新用量”只读取套餐，不更新节点；“刷新节点”处理节点后另行读取套餐。套餐刷新独立于节点预览或内核是否有效。
- 左下速率与累计是本次内核运行的本机流量，和套餐累计分别显示。日志每秒采样目标域名/IP、端口和节点链路，内存保留最近 300 条，短连接可能漏采。
- 普通测速不等于 Codex 模型速度；未认证的 Codex 检测不能保证地区、账号权限或真实模型调用。WSL 后端尚未验证。

## 代理范围

通过新启动进程的环境变量和 Chromium 参数为 Codex 及继承设置的子进程配置代理；HTTPS 使用本地 CONNECT 隧道，不解密 TLS。

不修改 Windows 系统代理、WinHTTP、路由或 TUN，不改系统环境变量，不替其他程序主动设置代理。它不是按进程防火墙；子工具是否走代理取决于自身实现，外部 OAuth 浏览器不会自动继承代理，电脑已有的全局代理或 TUN 仍由原工具控制。

## 隐私与更新

状态默认保存在 `%LOCALAPPDATA%\codex-proxy`。订阅 URL、节点凭据和本地代理认证信息是**本地明文**，目录使用当前用户权限限制，没有加密存储。不要上传整个状态目录、原始内核日志或带凭据的链接；界面连接日志不展示请求路径、查询参数或认证头。

套餐读取向订阅地址按所选路径发起 GET，只读响应头，固定 UA `clash-verge/v2.5.9`，节点下载采用相同 UA；标准及 `*-subscription-userinfo` 兼容头支持大小写和部分字段。首次打开、切订阅或手动刷新可能产生此请求，缓存不代表实时数据。系统代理的上游认证可能写入本地内核配置，同样是受目录权限保护的明文，不上传状态目录。

首次打开“设置 → 更新”会异步查询本仓库 GitHub Releases，包含预览版；也可手动检查。GitHub 匿名 API 额度按出口 IP 共享，限流或网络/服务错误时改读仓库公开的 `updates/latest.json`，标明“公开版本清单”来源。清单由 Release 发布流程维护，可能受 CDN 缓存延迟影响。最近成功结果本地缓存 5 分钟；手动检查可跳过缓存，但遵守服务器限流等待时间。两种来源都失败时保留已知发布版本和读取时间，显示失败，不冒充比较成功。

更新页只显示版本或打开发布页，不自动下载、替换或安装，也不向 GitHub 提交账号密码、Codex 登录令牌、订阅 URL 或 GitHub 令牌。应用更新查询在正式代理运行时复用专用代理，停止时使用系统默认代理，不会为查询自行启动内核。“检查内核更新”仍查询 Mihomo 官方 API，可能独立遇到 GitHub 限流，不使用本项目的版本清单。程序不设置开机自启动。

更多数据边界及报告方式见 [SECURITY.md](SECURITY.md)。
